# Traffic-to-Domain Risk Monitor

Capstone 2026 Team 40 built a Rust-based monitoring pipeline that turns raw network observations into domain-level security context.

The system starts from captured traffic, resolves observed IP addresses back to possible domains, scores the result, and escalates only the targets worth deeper probing. The result is a compact local investigation console: fewer raw packets to inspect, more explainable alerts to review.

## Project Overview

- Traffic capture works with live interfaces and `.pcap` files.
- Reverse IP lookup resolves observed IPs into candidate domains.
- Risk scoring classifies domains into `skip`, `watch`, and `probe` decisions.
- Active probing collects HTML, redirect information, screenshots, assets, and related metadata for high-risk domains.
- The Rust dashboard presents status, alerts, domains, and probe results.

## Product Shape

The application provides five main views:

- Dashboard metrics for total domains, active alerts, captured IPs, and probe runs.
- Alerts view with severity, alert type, detail, timestamp, and acknowledgment state.
- Domains view with risk score, decision, IPs, last seen time, and alert count.
- Domain detail pages with IP history, alerts, risk signals, and snapshots.
- Probe flow for reverse IP lookup with optional source selection and verification.

## Why This Matters

Security triage often begins with an IP address but needs domain context before a useful decision can be made. This project narrows that gap by combining passive capture, reverse lookup, scoring, and focused probing into one local workflow.
